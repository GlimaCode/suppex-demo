# SUPPEX — پروتوتایپ فروشگاه مکمل ورزشی

پروتوتایپ استاتیک و کاملاً کارکردی برای ارائه و تأیید UI/UX، پیش از شروع فاز Backend.
بدون Build Process، بدون وابستگی به npm، و قابل اجرا با دابل‌کلیک.

**Design Direction:** A — Premium، به‌علاوه ۲۰٪ انرژی از Direction B
**زبان:** فارسی، `dir="rtl"` · نام محصولات و دسته‌ها لاتین · اعداد لاتین

---

## اجرا

### روش ۱ — بدون هیچ ابزاری (برای ارائه به کارفرما)

کافی است روی `index.html` دابل‌کلیک کنید.

کل پروژه عمداً طوری نوشته شده که روی پروتکل `file://` کار کند:

- هیچ `import`/`type="module"` استفاده نشده (توسط CORS روی `file://` بلاک می‌شود)
- هیچ `fetch()` روی فایل‌های محلی انجام نمی‌شود — کاتالوگ و مدل سه‌بعدی هر دو `<script>` معمولی هستند
- هیچ مسیر مطلقی (`/assets/...`) وجود ندارد؛ همه مسیرها نسبی‌اند

### روش ۲ — با وب‌سرور محلی (توصیه‌شده برای توسعه)

```bash
python -m http.server 8000
```

سپس `http://localhost:8000` را باز کنید.

> فایل `.claude/launch.json` صرفاً یک تنظیم اختیاری برای ابزار پیش‌نمایش است و نقشی در خروجی ندارد.

### روش ۳ — انتشار رایگان روی GitHub Pages

پروژه هیچ مسیر مطلقی ندارد، بنابراین روی زیرمسیر هم درست کار می‌کند — یعنی آدرسی
مثل `username.github.io/repo-name/` بدون هیچ تغییری بالا می‌آید. (تست شده: همه
فایل‌ها از زیرمسیر ۲۰۰ می‌گیرند و مدل سه‌بعدی هم لود می‌شود.)

۱. در github.com یک اکانت رایگان بسازید
۲. یک ریپازیتوری **Public** جدید بسازید
۳. محتویات همین پوشه را با Add file ← Upload files آپلود کنید
۴. Settings ← Pages ← Source: `main` و پوشه `/ (root)`
۵. حدود یک دقیقه بعد لینک آماده است

نکته: پلن رایگان GitHub Pages فقط برای ریپازیتوری Public است، یعنی کد قابل مشاهده
خواهد بود. برای یک دموی ارائه معمولاً مشکلی نیست.

### نیاز به اینترنت

فقط برای دو مورد **خارجی**: فونت‌های Google و کتابخانه Three.js از CDN.
اگر آفلاین باشید، سایت همچنان کامل کار می‌کند — فونت به `system-ui` و بخش سه‌بعدی به تصویر ثابت برمی‌گردد.

## چه چیزهایی در این فاز ساخته شده

### صفحه اصلی
نوار اعلان · هدر چسبان با منوی موبایل · هیرو با مدل سه‌بعدی محصول · تیکر متحرک · نوار رسانه‌ها ·

بنر کمپین با **شمارش معکوس زنده** · بخش استاندارد برند · نظرات · مجله · فوتر کامل با خبرنامه و نمادهای اعتماد

- **دراور سبد** و **اورلی جستجو** با بستن از طریق `Esc` و کلیک روی پس‌زمینه
- اعلان‌های Toast
- انیمیشن ورود تدریجی هنگام اسکرول

## معماری — آمادگی برای فاز Backend

پروژه سه «درز» مشخص دارد که فاز بعدی از همان‌ها وارد می‌شود، **بدون بازنویسی UI**:

### ۱. لایه Repository — مهم‌ترین نقطه

تمام متدهای `repo.js` از همین حالا `Promise` برمی‌گردانند، حتی وقتی داده از حافظه خوانده می‌شود.
برای اتصال به Backend فقط این یک خط عوض می‌شود:

```js
// assets/js/config.js
api: { baseUrl: null }                 // ← فعلاً: کاتالوگ محلی
api: { baseUrl: 'https://api.suppex.ir' }   // ← بعداً: درخواست HTTP واقعی
```

`repo.js` خودش تشخیص می‌دهد و به `fetch` سوییچ می‌کند. **هیچ فایل دیگری تغییر نمی‌کند**،
چون هیچ کامپوننتی مستقیماً به داده دست نمی‌زند.

### ۲. لایه Store

`store.js` یک استور observable با `subscribe()` است. سبد خرید سمت سرور فقط یعنی تغییر
`load()` و `save()` — بقیه کد دست‌نخورده می‌ماند.

### ۳. لایه UI

توابع `ui.js` خالص‌اند: داده می‌گیرند، رشته HTML برمی‌گردانند. نه به استور دست می‌زنند،
نه به DOM. همین باعث می‌شود انتقالشان به هر Template Engine یا فریم‌ورکی مستقیم باشد.

### قراردادهای دیگر

- **پول همیشه عدد صحیح (تومان) است**، نه رشته فرمت‌شده. فرمت‌دهی فقط در
  `config.currency.format()` انجام می‌شود — تغییر به ریال یک تابع است.
- **قوانین تجاری در View نیستند**: درصد تخفیف، آستانه ارسال رایگان و جمع کل
  همگی در `repo.js` و `store.js` محاسبه می‌شوند.
- **فلگ‌ها**: `config.flags` اجازه می‌دهد حالت‌های مختلف (کمپین فعال/غیرفعال، سه‌بعدی
  روشن/خاموش) در جلسه بازبینی زنده تغییر کند.
- **تمام ورودی‌های داده escape می‌شوند** (`ui.esc`) — الگوی امن از همین فاز جا افتاده است.

## فاز اول: سفارش بدون درگاه پرداخت

`config.ordering.method` تعیین می‌کند سفارش چطور ثبت شود:

```js
ordering: {
  method: 'telegram',              // 'telegram' | 'whatsapp' | 'gateway'
  telegramUsername: 'suppex_shop', // بدون @
  whatsappNumber: '989121234567',
}
```

با `telegram` یا `whatsapp`، دکمه پایان سبد خرید کل سفارش را به‌صورت یک پیام آماده
در همان اپ باز می‌کند. یعنی فروشگاه بدون **درگاه پرداخت، نماد اعتماد و ثبت شرکت**
قابل راه‌اندازی است و سفارش‌ها همان‌جایی می‌رسند که فروشنده الان کار می‌کند.

فاز دوم فقط `method` را به `'gateway'` تغییر می‌دهد؛ سبد خرید و کاتالوگ دست‌نخورده می‌مانند.

### شماره کارت خودکار

پس از زدن دکمه سفارش، تلگرام باز می‌شود **و** داخل سبد خرید مبلغ نهایی به‌همراه
شماره کارت و نام صاحب حساب نمایش داده می‌شود — یعنی فروشنده هیچ‌وقت لازم نیست
شماره کارت را دستی بفرستد.

```js
payment: {
  method: 'card',                     // 'card' | 'gateway' | 'none'
  cardNumber: '6037 9911 0000 0000',  // ← شماره واقعی را اینجا بگذارید
  cardHolder: 'نام صاحب حساب',
  bankName: 'بانک ملی',
}
```

**دو محافظ عمدی:**

۱. شماره کارت پیش‌فرض **از قصد نامعتبر است** — رقم کنترلی Luhn را رد می‌کند، پس اگر
این نسخه بدون ویرایش منتشر شود بانک هر واریزی را برمی‌گرداند و پول کسی به حساب
ناشناس نمی‌رود. هنگام بالا آمدن صفحه هم اگر شماره معتبر نباشد، در کنسول هشدار
داده می‌شود.

۲. شماره کارت **فقط بعد از ثبت سفارش** دیده می‌شود، نه روی صفحه عمومی. شماره کارتی
که آزادانه روی وب منتشر شود، برای کلاهبرداری به نام همان فروشگاه استفاده می‌شود.

دکمه «کپی شماره» اگر کلیپ‌بورد در دسترس نباشد (مثلاً روی `http` بدون TLS)، به روش
قدیمی سوییچ می‌کند و **اگر آن هم شکست بخورد صادقانه می‌گوید کپی نشد** — به‌جای
اینکه «کپی شد» نشان دهد و کاربر چیزی در دستش نباشد.

### فلگ‌های اعتماد

```js
showRatings: false,       // ستاره و تعداد نظر روی کارت محصول
showTestimonials: false,  // بخش نظرات، نوار رسانه‌ها، امتیاز در نوار بالا
```

این دو **عمداً خاموش‌اند**. ستاره و تعداد نظر تنها بخشی از فروشگاه‌اند که نمی‌شود
با محتوای نمونه پر کرد: عدد ساختگی روی یک دمو، کل کار را غیرصادقانه جلوه می‌دهد و
فروشگاهی که هنوز راه نیفتاده هم نظری برای نشان دادن ندارد. بعد از سفارش‌های واقعی
روشنشان کنید.

### تصویر پیش‌نمایش لینک

`assets/images/og-cover.png` با اندازه ۱۲۰۰×۶۳۰ ساخته شده و در تگ `og:image` هر دو
صفحه نشسته است. **فرمت SVG اینجا کار نمی‌کند** — تلگرام و واتس‌اپ آن را رندر نمی‌کنند
و لینک بدون تصویر فرستاده می‌شود.

## سیستم طراحی

تمام مقادیر در `assets/css/tokens.css` تعریف شده‌اند. تغییر برند یعنی تغییر همین فایل.

| نقش | مقدار |
|---|---|
| پس‌زمینه | `#131210` گرافیت گرم (نه مشکی خالص) |
| سطوح | `#1C1A17` → `#242019` → `#2C2721` |
| متن | `#F2EDE3` استخوانی |
| اکسنت | `oklch(0.66 0.20 40)` مسی-آجری |
| اکسنت روشن | `oklch(0.72 0.17 45)` کهربایی — امتیاز و تأکید |
| موفقیت | `oklch(0.72 0.15 145)` — فقط وضعیت موجودی |

رنگ‌ها با `oklch` نوشته شده‌اند (فضای رنگی ادراکی، مطابق فایل‌های مرجع) و برای هر کدام
**fallback هگز** هم تعریف شده تا در مرورگرهای قدیمی‌تر افت نکنند.

**تایپوگرافی — تفکیک بر اساس خط، نه بر اساس نقش:**

| خط | فونت | کجا |
|---|---|---|
| فارسی | `Vazirmatn` وزن ۴۰۰–۹۰۰ | بدنه، تیترها، دکمه‌ها، نام فارسی محصولات، قیمت‌ها |
| لاتین | `Archivo Black` | لوگو، وردمارک فوتر، تیکر، اعداد نمایشی (آمار، ۰۱/۰۲/۰۳، شمارش معکوس، امتیاز) |
| لاتین | `Archivo` وزن ۴۰۰–۸۰۰ | نام لاتین محصولات (کلاس `.lat`) |
| لاتین | `Instrument Serif` | تأکید ادیتوریال در دو نقطه (نوار رسانه‌ها و تیتر بخش محصولات) |

> **چرا نقش نمایشی وزن نمی‌گیرد:** `Archivo Black` خانواده تک‌وزنه‌ای است که در
> Google Fonts با وزن **۴۰۰** ثبت شده. اگر روی آن `font-weight: 900` بگذارید، مرورگر
> روی فونتی که خودش سیاه است **بولد مصنوعی** اعمال می‌کند و حروف کثیف و پخش می‌شوند.
> برای همین قوانینی که از `--font-display` استفاده می‌کنند عمداً هیچ `font-weight`
> تعریف نمی‌کنند. اگر روزی این نقش به یک فونت متغیر تغییر کرد، آن‌وقت باید وزن صریح
> اضافه شود — وگرنه با وزن ۴۰۰ نازک رندر می‌شود.

امضای بصری فایل‌های مرجع (تیتر دو-صدایی) در فارسی با تغییر وزن و رنگ بازسازی شده،
چون معادل «سریف ایتالیک» در فارسی وجود ندارد.

### لایه انرژی (۲۰٪ از Direction B)

پایه Premium دست‌نخورده مانده — پالت، فونت‌ها و فاصله‌گذاری همان است. فقط چند عنصر
کنترل‌شده از جهت «باشگاه حرفه‌ای» اضافه شده، و **همگی از یک جا تنظیم می‌شوند**:

```css
/* assets/css/tokens.css */
--energy-angle: 115deg;   /* زاویه تمام خطوط مورب       */
--energy-line:  rgba(242, 89, 20, 0.14);
--ticker-speed: 20s;      /* در نسخه آرام‌تر: 32s        */
--cut:          clamp(15px, 3vw, 38px);  /* گوشه بریده بنر */
```

| عنصر | قبل | بعد |
|---|---|---|
| سرعت تیکر | ۳۲ ثانیه، ۱۳px | **۲۰ ثانیه**، `Archivo Black` ۱۴px + بافت هاشور مورب |
| اعداد آمار هیرو | ۳۰px | **۴۶px** `Archivo Black` + خط اکسنت بالای هر ستون |
| شماره‌های ۰۱/۰۲/۰۳ | ۱۴px توپر | **۴۰px تورفته با خط دور** (`-webkit-text-stroke`) |
| شمارش معکوس | ۲۷px | **۴۶px** + نوار اکسنت بالای هر خانه |
| امتیاز ۴.۹ | ۵۴px | **۷۴px** |
| بنر کمپین | گوشه گرد ۲۶px | **گوشه بریده صنعتی** + خطوط مورب پررنگ‌تر |
| Overline سکشن‌ها | متن ساده | **تیک هاشور مورب** پیش از هر عنوان |

تیک هاشور با یک قانون روی `.u-eyebrow::before` پیاده شده، پس روی همه سکشن‌ها یکسان
می‌نشیند. در کارت‌های مجله که فضا تنگ است با `.u-eyebrow--bare` خاموش می‌شود.

شماره‌های تورفته با `@supports` محافظت شده‌اند: مرورگری که `-webkit-text-stroke` را
نمی‌شناسد، همان عدد توپر رنگی را نشان می‌دهد.

اندازه `--cut` همیشه کوچک‌تر از padding خود بنر می‌ماند (۳۸px در برابر ۷۲px روی دسکتاپ،
۱۵px در برابر ۳۶px روی موبایل) تا گوشه بریده هرگز محتوا را نبرد.

**برای کم یا زیاد کردن شدت:** `--ticker-speed` را بالا ببرید و `--energy-line` را
کم‌رنگ‌تر کنید تا به نسخه آرام برگردد؛ برعکسش شدت را بیشتر می‌کند.

**نکته RTL:** هیچ استایل جداگانه‌ای برای RTL نوشته نشده. کل CSS از
Logical Properties استفاده می‌کند (`inset-inline-start`, `padding-block`, `margin-inline`)
و به‌صورت خودکار قرینه می‌شود. تغییر به LTR فقط با عوض کردن `dir` در تگ `<html>` انجام می‌شود.

## مدل سه‌بعدی

مدل هیرو، قوطی وی ایزوله است (`whey-isolate-tub.obj`) — یعنی همان چیزی که فروشگاه
واقعاً می‌فروشد. فایل اصلی ۸۹۶ کیلوبایت بود، عمدتاً چون اعداد اعشاری با دقت کامل ذخیره
شده بودند نه به‌خاطر سنگینی هندسه.

**راه‌حل اعمال‌شده:** تبدیل به فرمت باینری فشرده و جاسازی به‌صورت base64:

| | |
|---|---|
| موقعیت رأس‌ها | `Int16` کوانتیزه‌شده روی Bounding Box |
| مختصات UV | `Uint16` روی بازه ۰..۱ |
| بردار نرمال | `Int8` |
| ایندکس‌ها | `Uint16` |
| هندسه | ۴,۰۶۴ رأس / ۷,۳۶۰ مثلث |
| متریال‌ها | ۳ گروه، مستقیماً از `whey-isolate-tub.mtl` |
| **نتیجه** | **۸۹۶KB → ۱۳۴KB** (هندسه بدون تغییر) |

**چرا هندسه از OBJ و طرح از GLB:** فایل `.glb` حجمش ۱.۸ مگابایت است و `GLTFLoader`
در نسخه‌های جدید Three.js فقط به‌صورت ES Module عرضه می‌شود — یعنی دقیقاً همان چیزی که
اجرای بدون سرور را خراب می‌کند. اما با باز کردن GLB مشخص شد تنها محتوای اضافه‌اش
**یک تکسچر PNG** است که فقط به متریال `label-print` وصل شده؛ بدنه و درب همان رنگ ثابت
MTL را دارند.

پس طرح برچسب از داخل GLB بیرون کشیده شد و روی همان هندسه سبک OBJ نشست. این کار قابل
اتکا بود چون بررسی شد که پچ برچسب در هر دو فایل **دقیقاً یکسان** است: ۱۹۴ رأس، UV در
بازه ۰..۱، و `v` رو به بالا.

| | |
|---|---|
| PNG اصلی داخل GLB | ۱۴۰۰×۱۲۹۱ — ۱.۷ مگابایت |
| پس از تغییر اندازه و WebP q88 | ۷۶۸×۷۰۸ — **۷۷ کیلوبایت** |
| به‌صورت data URI در `label.tex.js` | ۱۰۸ کیلوبایت |

**چرا data URI و نه فایل تصویری جدا:** روی `file://` تصویری که از یک URL دیگر بارگذاری
شود، هنگام آپلود به WebGL «آلوده» (tainted) حساب می‌شود و رندر شکست می‌خورد. data URI
هم‌مبدأ است و این مشکل را ندارد. همین دلیل برای خود مدل هم صدق می‌کند، چون `fetch`
روی `file://` بلاک می‌شود.

اگر `label.tex.js` نبود، یک برچسب ساده روی `<canvas>` به‌عنوان fallback کشیده می‌شود
تا سطح برچسب سفید خالی نماند.

**حرکت:** به‌جای چرخش کامل، قوطی حول جلو تاب می‌خورد. دلیلش این است که برچسب فقط
۱۴۰ درجه از محیط قوطی را می‌پوشاند و چرخش کامل، بیشتر وقت‌ها پشت بی‌طرح را نشان می‌داد.

**زنجیره ایمنی:**

1. فلگ `show3DHero` روشن باشد
2. کاربر `prefers-reduced-motion` نداده باشد
3. WebGL در دسترس باشد
4. عرض صفحه ≥ ۳۲۰ پیکسل — یعنی **موبایل هم مدل سه‌بعدی را می‌بیند**
   (کسی که لینک را می‌گیرد با گوشی بازش می‌کند و هیرو مهم‌ترین بخش صفحه است)
5. اتصال کُند یا Save-Data فعال نباشد — روی 2G یا حالت صرفه‌جویی، پوستر می‌ماند
   و هیچ‌چیز دانلود نمی‌شود. 3G عمداً مستثنا نیست، چون پوستر از قبل روی صفحه است
   و مدل هر وقت رسید محو می‌شود داخل
6. هیرو نزدیک کادر دید باشد (حاشیه ۲۰۰ پیکسل)

اگر هر کدام رد شود، پوستر ثابت `hero-tub.svg` که از ابتدا در HTML هست باقی می‌ماند —
بدون پرش چیدمان و بدون فضای خالی.

دو شرط آخر **در لحظه تصمیم** ارزیابی می‌شوند، نه یک بار موقع لود. سه محرک مستقل
وجود دارد: بررسی مستقیم هنگام init (هیرو تقریباً همیشه بالای صفحه است)،
`IntersectionObserver` برای حالتی که پایین‌تر باشد، و رویداد `resize` برای وقتی که
کاربر پنجره کوچک را بزرگ می‌کند. یک فلگ `started` تضمین می‌کند فقط یک بار اجرا شود.

**نورپردازی:** فلزات برای دیده‌شدن به بازتاب نیاز دارند. چون ماژول `RoomEnvironment` نیازمند
ES Modules است (و در نتیجه سرور)، یک **Environment Map روی Canvas** به‌صورت رویه‌ای ساخته
می‌شود: سه سافت‌باکس (کلید گرم، پرکننده سرد، بازتاب پایینی نارنجی) که به کروم عمق می‌دهند.

**مقیاس دوربین:** ضریب `2.02` به‌صورت عددی حل شده تا مدل در **تمام زوایای چرخش** و در
بیشینه پارالاکس نشانگر، داخل ۸۸٪ کادر بماند (بدترین حالت وقتی است که دمبل کاملاً عرضی می‌ایستد).

## تصاویر Placeholder

هر ۲۷ تصویر، فایل SVG واقعی روی دیسک هستند — نه کادر خاکستری. سه قالب ظرف
(قوطی پودر، پوچ فویلی، بطری قرص) با رنگ‌بندی متمایز هر دسته‌بندی.

**جایگزینی با عکس واقعی:** فقط مقدار `image` و `gallery` در `catalog.js` را عوض کنید.
قاب، نسبت تصویر (`1:1` محصول، `4:5` دسته، `16:10` مقاله) و شعاع گوشه‌ها ثابت می‌مانند
و هیچ تغییری در HTML یا CSS لازم نیست.

### محدودیت‌های شناخته‌شده در این نسخه

- دکمه «ادامه فرآیند خرید» عمداً یک Toast نشان می‌دهد؛ تسویه در فاز بعد است
